# antislop audit 001 (2026-11-09)

Scope: the whole Tally app (Partner and Employee views) as built from Figma frame `37:15126`.
Mode: after. Nothing has been changed yet. Pick the numbers you want fixed.

**Origin** says where the pattern comes from:
- **Figma**: drawn in the frames. Fixing it means departing from the design.
- **Code layer**: from the prototype source in node `36:3`, which I ported for states with no frame.
- **Build**: a choice I made while implementing.

Priority follows the rule tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Lock = LOW.

Contrast ratios below were measured with the WCAG contrast checker, against the real background (semi-transparent surfaces composited over the page color `#f3f0e9`). Almost all text in this design is 7 to 13px, so the 4.5:1 normal-text threshold applies.

**2. White text on the orange unread badge is 2.58:1.** R-25. Origin: Code layer.
The Messages unread badge uses white 11px text on `#ff7b31`.
Fix: use the dark clay accent as the badge color, or dark text on the orange.

**3. Em dashes in visible copy.** R-02. Origin: Code layer.
The Employee project drawer shows "Submitted — 9.7 hours recorded" and "Draft — 8.5 hours recorded" (`src/data/progress.ts:47,49`).
Fix: "Submitted: 9.7 hours recorded".

**4. Most controls show the arrow cursor instead of the pointer.** R-39. Origin: Build.
Tailwind v4's reset sets buttons to `cursor: default`, and only 2 elements override it. Disabled controls mostly lack `cursor: not-allowed`.
Fix: one base rule in `index.css` for `button`, `a[href]`, `summary`, `select`, `label[for]`, radio/checkbox labels and `[role=tab|switch]`, plus `:disabled { cursor: not-allowed }`.

**5. The Google Fonts stylesheet blocks first render.** R-40. Origin: Build.
`index.html` loads `fonts.googleapis.com/css2…` as a blocking `<link>` in `<head>`, so nothing paints until Google responds. No performance numbers were measured.
Fix: self-host with `@fontsource-variable/dm-sans` and `@fontsource/doto`, which CLAUDE.md allows. That adds 2 dependencies.

**6. Controls that do nothing.** R-26. Origin: Figma (controls drawn), Code layer (also inert there).
- Partner header "May 2025 ⌄" button
- Header avatar button ("VH" / "NC")
- Settings, Billing rules: "Set by project" (×5)
- Settings, Integrations: "Not connected" (×4)
- Settings, Data & privacy: "Export firm data", "Review retention settings"

Fix, per control: render it as plain text where it's really a label ("May 2025", avatar). Otherwise keep the button with a visible "Coming soon" label and a `// TODO` in code. "Not connected" reads naturally as a status, so it could become a status label instead of a button.

**7. Numbers that don't follow the data.** R-17 / R-38. Origin: Figma and Code layer (hard-coded there too).
The demo is labeled synthetic, but these values stay fixed while the rest of the app changes:
- Partner Home hero: "01 timesheet missing", "02 ready for billing"
- Needs attention: "2 review questions" and "Maya is overdue" (still say 2 after both flags are resolved)
- Home table: Coleman's "Time missing" completeness
- Employee Home: "04 days left", "On track"
- Team table: "May 29" / "Apr 30" last submission

Fix: derive each from the store: open flags, submissions, the pinned demo date (May 30, 2025 → June 3 = 4 days), entry dates.

**8. Excel import has no error state.** R-27. Origin: Build.
Dropping any file, even a PDF, is "read" as the demo spreadsheet.
Fix: check for `.xlsx` / `.xls` and show an error state that names the problem and the next step. That needs new copy, which I'd draft for your approval. Elsewhere, data is in memory with no fetching, so loading and error states don't apply; the import's "Reading columns…" step is the only real loading state.

**9. Heading levels skip, and there's no footer landmark.** R-39. Origin: Build.
- Clients & Projects: card titles are `h3` directly under the page `h1`.
- Invoice review: the invoice's client name is an `h3` before the panel's `h2`.
- Time Entries: the "Reading columns…" state is an `h3` under the `h1`.
- My Projects: the empty state is an `h3` under the `h1`.
- The app shell has `header`, `nav` and `main`, but no `footer`. The design has none.

Fix: re-level those headings to `h2`. For the footer, either add a minimal one (no content is designed for it) or record the exception.

**10. The entry search box has no visible label.** R-39. Origin: Code layer.
The search field in the entries toolbar is labeled only by `aria-label` and its placeholder.
Fix: a small visible "Search" label inside the search pill.

**11. Keyboard details.** R-32 / R-39. Origin: Build.
Everything is reachable with Tab and Enter, and dialogs close with Esc. However:
- Tab lists (`role="tablist"` on Time Entries, Settings and My Projects) don't support arrow keys, which screen-reader users expect for that role.
- The text-field focus outline is only 20% opacity. The darker border helps, but the ring itself is faint.

Fix: arrow-key handling in one shared Tabs component, and a solid focus outline on fields.

**12. Desktop only.** R-03. Origin: your decision (2026-11-09).
Below 1100px the app scrolls sideways. Several targets are under 44px: the role toggle (26px), toolbar icons (29px), the row menu (28px). Listed so the exception is on record; fix only if you reverse that decision.

## MEDIUM

Each can be kept with a one-line reason, which I'd add to the code and to the DESIGN.md in #20, or changed.

**13. Frosted glass on 4 surfaces.** R-10. Origin: Figma (header, sidebar), Code layer (modal and drawer backdrops).
Fix: keep blur on the header only (it scrolls over content) and make the sidebar solid.

**14. Peach glow behind every page.** R-01. Origin: Figma (Shell fill).
The radial glow sits on every screen, on top of two hero gradients.
Fix: drop the page-wide glow and keep the hero gradients, where they mark the one "next step" card. Or keep it with a written brand reason.

**15. Sparkle icon.** R-04. Origin: Figma.
Used on "View how Tally worked" and in the dark circle next to "Review with Tally".
Fix: an icon relevant to what it opens (activity list / checklist), or no icon.

**16. Pill above a heading.** R-09. Origin: Figma.
- "Your next step" above "Review 2 invoices" (repeats what the card already says)
- "Due June 3" above "Your time is almost ready" (carries information the heading lacks, so it can stay)
- "5 columns detected" above "Confirm column mapping"

Fix: drop "Your next step"; keep the other two with a reason.

**17. Decorative status dot.** R-31 / R-13. Origin: Figma.
The green dot with a halo next to "Interactive prototype" looks like a live indicator but marks nothing.
Fix: remove the dot and keep the text. The orange dot on the newest reminder-activity line marks real state and is fine.

**18. Uppercase tracked labels and the dot-matrix counter font.** R-06. Origin: Figma.
Eyebrows ("MAY BILLING CYCLE"), sidebar group labels, table headers, card meta labels. Doto (dot-matrix) for counters.
Fix: write the reasons (eyebrow = billing-period context; Doto = Tally's identity motif for counts) or drop the uppercase/tracking on the meta labels.

**19. Arrows on buttons.** R-08. Origin: Figma (Review invoices →, Log time →, Open →, Review →, card chevrons); Code layer (Continue →, Create project →).
Fix: keep arrows only on controls that move to another page; remove them from "Continue" and "Create project" in the New Project form.

## LOW

**20. No written design direction.** R-31 / R-37. Origin: Build.
The Figma file is the direction, but the reasons and dials aren't written down anywhere except scattered comments in `tokens.css`.
Fix: add `DESIGN.md` with the Design Read, dials (proposal: ENERGY 1 / RHYTHM 2 / MOTION 1) and a one-line reason for each major choice.

**21. A second accent color.** R-29. Origin: Code layer.
Bright orange `#ff7b31` (New Project step bar, unread badge, spinner, newest-activity dot) competes with the clay accent. Purple and blue project-card tints add two more hues.
Fix: move the orange uses onto the clay accent; keep the tints as the per-project motif with a reason.

**22. Light theme only.** R-21. Origin: Figma.
No dark theme exists in the design.
Fix: write the reason (the cream "paper" surface matches the invoice-document metaphor). Building a dark theme would be a large separate task.
